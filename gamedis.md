Game Design Document — Dream Shards
1. Общее описание

Жанр: 2D платформер
Камера: Сайд-скролл
Референсы: Karmazoo, Celeste (по ощущениям контроля), Limbo (по атмосфере)
Целевая сессия: 2–3 минуты на уровень

Концепт:
Игрок управляет персонажем, путешествующим через серию снов. Каждый уровень — отдельный сон с уникальной визуальной и механической темой. Основная цель — собрать 3 осколка сна и добраться до портала, который появляется после их сбора.

2. Core Gameplay Loop
Игрок появляется в начале уровня (сна)
Исследует пространство
Преодолевает платформенные препятствия
Находит и собирает 3 осколка
После сбора всех осколков открывается портал
Игрок достигает портала → завершение уровня → переход в новый сон
3. Основные механики
3.1 Передвижение
Бег
Прыжок (основной + возможен double jump / вариации позже)
Скользящие поверхности / изменение гравитации (в зависимости от сна)
Coyote time (~8 кадров после схода с платформы — прыжок ещё допустим)
Jump buffer (~8 кадров — раннее нажатие засчитывается при приземлении)
Variable jump height (отпускание клавиши прыжка обрезает дугу)
Burst-частицы при двойном прыжке
3.1.1 Горизонтальная гравитация (Сон 6 — Горизонтальный)

Описание механики:
Гравитация действует по оси X, притягивая игрока к левой или правой стене.
Стена, к которой тянет, является «полом» — игрок стоит на ней ногами и бежит вдоль неё.
Игрок может переключить направление тяги клавишами ← / →, меняя «пол» с левой стены на правую и обратно.

Управление:
  W / ↑       — движение вверх вдоль стены (увеличение скорости по Y)
  S / ↓       — движение вниз вдоль стены
  Space       — прыжок от стены (толчок в сторону, противоположную тяге)
  ←           — переключить тягу влево (левая стена становится полом)
  →           — переключить тягу вправо (правая стена становится полом)

Физика (параметры для Сна 6):
  gravity:   0.35  — ускорение тяги по оси X (px/кадр²)
  jumpForce: 18    — начальная скорость прыжка от стены (px/кадр)
  djForce:   15    — начальная скорость двойного прыжка
  moveSpeed: 4.5   — максимальная скорость движения вдоль стены (px/кадр)
  friction:  0.88  — замедление (множитель vy за кадр)

  Расчёт дальности прыжка:
    Одиночный прыжок: jumpForce² / (2 × gravity) ≈ 463 px
    Двойной прыжок:  +djForce² / (2 × gravity)  ≈ +321 px (итого ≈ 784 px)
  Это означает: с одной стены до другой (ширина уровня 1280 − 56 px стен = 1224 px)
  напрямую не добраться — нужно переключить тягу в полёте.

Кулдаун переключения гравитации: 18 кадров (предотвращает случайные двойные нажатия).

Поведение при переключении тяги в воздухе:
  - vx сбрасывается в 0 при переключении
  - canDoubleJump восстанавливается
  - Новая тяга немедленно начинает ускорять игрока в новом направлении
  - Игрок может прицелиться по Y с помощью W/S во время полёта и переключить тягу,
    чтобы «упасть» к нужной стене

Препятствия — вертикальные колонны:
  Платформы на уровне ориентированы вертикально (height >> width, обычно 28×150–350 px),
  параллельно стенам-полу. Колонна с прорывом состоит из двух частей:
    верхняя часть + GAP (свободное пространство 130–160 px) + нижняя часть.
  Игрок на стене прицеливается по Y, выравнивается с прорывом и прыгает сквозь него.
  Для прохождения нескольких колонн подряд нужно управлять Y в полёте (W/S).

Персонаж:
  Поворачивается на 90° в сторону активной стены:
    тяга влево  (gravityDir = −1) → угол поворота = +π/2
    тяга вправо (gravityDir = +1) → угол поворота = −π/2
  Ноги всегда направлены к активной стене (визуально стоит на ней ногами).

Визуальный индикатор активной стены:
  Активная стена («пол»):
    Цветная полоса шириной 28 px вдоль всего экрана
    Цвет: зелёный (#32c882) для левой стены, оранжевый (#dc8232) для правой
    Тайловые горизонтальные линии через каждые 40 px (создают ощущение пола)
    Яркая подсветка внутренней грани (3 px)
    Мягкое свечение за полосой (90 px gradient)
  Неактивная стена («потолок»):
    Тёмно-синяя полоса шириной 14 px
    Стрелки ← или → каждые 100 px подсказывают направление тяги к этой стене
  Пульсация обеих полос синхронизирована с синусоидой (период ~3 сек)

Индикатор в HUD (правый нижний угол):
  Круг с символом ← или → (цвет совпадает с активной стеной)
  Подпись «← → — flip»

Чекпоинты на уровне:
  Флажок повёрнут на 90° (основание направлено к стене, флажок торчит в уровень).
  Угол поворота совпадает с углом поворота персонажа для той же стены.
  Задаётся свойством drawAngle на объекте Checkpoint.

Звук переключения гравитации: SFX.gravityFlip() — тот же что в Сне 5.

Смерть:
  Падение за нижнюю границу (player.y > deathY)
  Выход за верхнюю границу (player.y + player.h < deathMinY)
  При возрождении у чекпоинта тяга сбрасывается в initialGravityDir (−1, влево).

3.3 Портал
Неактивен в начале уровня
Активируется после сбора всех осколков
Визуально усиливается (эффект "пробуждения")
3.4 Чекпоинты
Флажок, активируется касанием
При смерти игрок возрождается у последнего чекпоинта
1–2 чекпоинта на уровень
3.5 Кошмар-преследователь (Сон 4)
Спавн позади игрока со стартовой задержкой 2 секунды
Постоянно движется к игроку
Прыгает по платформам, если игрок выше на 60+ пикселей
Скорость растёт со временем (2.2 → 4.5)
Касание = смерть
Красное затемнение по краям экрана при приближении (~600px)
3.6 Исчезающие платформы (Сон 3)
При касании запускается таймер ~28 кадров с миганием
Платформа гаснет ~28 кадров, исчезает, возвращается через ~110 кадров
3.7 Пружинка-джампер (Сон 4)
Визуальный стиль — пружина из Sonic: жёлтый верх с диагональными оранжевыми полосами, красное основание с боковыми бликами, три красных шеврона-стрелки сверху, тень под низом
Размер 44×28, своя физика: гравитация, трение (vx*=0.85), коллизии с платформами
Подвижная — игрок толкает её сбоку; при упоре пружины в платформу останавливается игрок
При прыжке на верх подбрасывает игрока вверх (launchForce: 26 — пик ~600px над пружиной)
Гасит горизонтальный импульс игрока (vx=0) при отскоке — полёт строго вертикальный, легче целиться по парящему осколку
Bell-curve анимация сжатия-разжатия: ~18 кадров, до 55% сжатия с возвратом к исходной форме
Звук "boing" — sawtooth-sweep 180→880→440 Гц через LPF
Защита от падения в пропасть: при падении ниже deathY автоматически возвращается на стартовую позицию
Респаун: при смерти после активации чекпоинта пружина появляется рядом с чекпоинтом (~60px справа), а не возвращается в начало уровня
Применение: на Сне 4 один из осколков висит высоко в воздухе (y=300) — единственный способ достать = подкатить пружину под осколок и прыгнуть на неё; платформы рядом с осколком убраны для чистого вертикального коридора
Сон 4 имеет сплошной пол без ям (изначально были разрывы — убраны, чтобы пружина не падала в пропасти при толкании)
3.8 Течения (CurrentZone)  (Сон 1)
Горизонтальная зона, невидимая для игрока (визуально — синяя полоса со стрелками)
Постоянно прикладывает силу к горизонтальной скорости игрока пока он внутри зоны
Сила ограничена значением moveSpeed — игрок не разгоняется бесконечно
Используется для направления игрока в шипы или ямы
Применено в Сне 1: шесть зон течений, две из них пульсирующие (PulsingCurrentZone)
Реализация: class CurrentZone(x1, x2, force); applyTo(player) добавляет force к vx каждый кадр
3.9 Телепорт-порталы (TeleportPortal)  (Сон 1)
Золотой портал, стоит на платформе
При касании мгновенно перемещает игрока в заданные координаты
Кулдаун 90 кадров (1.5 сек) после телепорта — повторный вход невозможен
Использован для доступа к секретной платформе (y=80), недосягаемой прыжком
Визуально: вращающийся золотой эллипс с лучами, без текстовой метки
Реализация: class TeleportPortal(x, y, destX, destY); checkTeleport(player) при коллизии
3.10 Шипы и ямы (Hazard + floor gaps)  (Сон 1)
Шипы — прямоугольные зоны урона (Hazard) вровень с полом, высота 24px
Ямы — разрывы в напольных платформах; падение = смерть (deathY=730)
В Сне 1 шипы расставлены внутри зон течений: касание = смерть,
  если игрок не прыгнул — течение затаскивает его дальше в яму
Реализация: class Hazard(x, y, w, h); пересечение с игроком → player.die()
4. Level Design
4.1 Структура уровня (по аналогии с Karmazoo)

Уровень строится как:

Компактный маршрут (2–3 минуты)
С несколькими развилками
С возможностью:
выбрать порядок сбора осколков
возвращаться назад
4.2 Типовая схема уровня
Стартовая зона (безопасная)
Основной маршрут
2–3 ответвления:
короткие челленджи
платформенные секции
Точки с осколками:
1 — простой
1 — средний
1 — сложный / скрытый
4.3 Дизайн-принципы
Четкая читаемость
Минимальный downtime
Быстрое восстановление после ошибки
Каждый уровень вводит одну новую идею
4.4 Реализованные уровни (6 шт.)
Сон 1 — Спокойный (туториал, дефолтная физика, ширина 2560)
  Новые механики: течения, телепорт-портал, шипы, ямы в полу
  3 зоны течений — каждая ведёт игрока к шипу, затем в яму
  1 телепорт-портал (x=1030, y=308) → секретная платформа (y=80)
  Осколок 3 (сложный) лежит на секретной платформе — только через портал
  5 разрывов пола: x 280–380, 590–680, 1050–1160, 1760–1870, 2120–2200
Сон 2 — Водный (гравитация 0.20, плавающее движение, ширина 2560)
Сон 3 — Ломаный (исчезающие платформы, ширина 3200)
Сон 4 — Кошмар (преследователь + пружинка-джампер для пазла с парящим осколком, ускоренный игрок moveSpeed 5.2, ширина 3840, сплошной пол)
Сон 5 — Падения (инверсия гравитации ↓/S, потолок и пол игровые, ширина 2560)
Сон 6 — Горизонтальный (горизонтальная гравитация ← →, левая/правая стена как пол, вертикальный уровень 1280×2700)

4.5 Сон 6 — Горизонтальный: детали уровня

Размеры: ширина 1280 px, высота 2700 px (вертикальный скролл)
Начальная тяга: влево (gravityDir = −1), игрок стартует на левой стене
Границы:
  Левая стена:  Platform(0, 0, 28, 2700)    — игрок приземляется на x = 28
  Правая стена: Platform(1252, 0, 28, 2700) — игрок приземляется на x = 1228
  Потолок:      Platform(0, −60, 1280, 60)
  Пол:          Platform(0, 2700, 1280, 60)

Структура уровня (4 секции, скролл вниз):

  Секция 1 (y=0–600): Открытая зона
    Без колонн — игрок осваивает управление
    Осколок 1: левая стена x=28, y=300 (просто спуститься)

  Секция 2 (y=600–1300): Две смещённые колонны
    Колонна A (x=420, w=28): верхняя y=660–820, прорыв y=820–960, нижняя y=960–1260
    Колонна B (x=780, w=28): верхняя y=660–1000, прорыв y=1000–1150, нижняя y=1150–1300
    Задача: войти в прорыв A (y≈880), нажать S в полёте, попасть в прорыв B (y≈1075)
    Осколок 2: правая стена x=1228, y=1075 — нужно переключить тягу вправо
    Чекпоинт 1: левая стена x=28, y=1100

  Секция 3 (y=1300–2000): Зеркальные колонны
    Колонна C (x=350, w=28): верхняя y=1340–1520, прорыв y=1520–1680, нижняя y=1680–1960
    Колонна D (x=820, w=28): верхняя y=1340–1460, прорыв y=1460–1620, нижняя y=1620–1960
    Прорывы смещены относительно друг друга — нужна корректировка Y в полёте

  Секция 4 (y=2000–2600): Тройной лабиринт
    Колонна E (x=280, w=28): верхняя y=2040–2200, прорыв y=2200–2360, нижняя y=2360–2580
    Колонна F (x=620, w=28): верхняя y=2040–2140, прорыв y=2140–2300, нижняя y=2300–2580
    Колонна G (x=960, w=28): верхняя y=2040–2080, прорыв y=2080–2240, нижняя y=2240–2580
    Прорывы сдвинуты так, что нужно успеть перестроиться по Y между каждой колонной
    Осколок 3: левая стена x=28, y=2220 — внутри прорыва колонны E
    Чекпоинт 2: левая стена x=28, y=2020
    Портал: правая стена x=1228, y=2550

Объекты на стенах:
  Левая стена: x=28 (внутренняя грань), объект перекрывает игрока (player.x=28)

13. Технические детали реализации

13.1 Горизонтальная гравитация — реализация в коде

Флаги уровня (объект уровня в levels.js):
  horizontalGravity: true   — включает режим горизонтальной гравитации
  initialGravityDir: -1     — начальное направление (−1 = влево, +1 = вправо)

Состояние игрока (класс Player, player.js):
  player.gravityAxis = 'x'  — переключает физический update на горизонтальную ось
  player.gravityDir  = ±1   — текущее направление тяги

Инициализация (loadLevel и respawn в game.js):
  if (level.horizontalGravity) {
    player.gravityAxis = 'x';
    player.gravityDir  = level.initialGravityDir || -1;
  }
  Выполняется как при первой загрузке уровня, так и при каждом возрождении.

Переключение тяги (игровой цикл PLAYING, game.js):
  Переменная gravityFlipCooldown — кулдаун 18 кадров
  ArrowLeft / KeyA  → player.gravityDir = −1; player.vx = 0; player.canDoubleJump = true
  ArrowRight / KeyD → player.gravityDir = +1; player.vx = 0; player.canDoubleJump = true
  SoundFX.gravityFlip() при каждом переключении

Метод _updateHorizontal (Player, player.js):
  Вызывается автоматически из update() когда gravityAxis === 'x'

  Движение вдоль стены (W/S или ArrowUp/ArrowDown):
    if (moveUp)   vy -= 1.2
    if (moveDown) vy += 1.2
    vy *= friction (0.88)
    clamp: |vy| <= moveSpeed

  Прыжок (Space):
    jumpBuffer = 8 при нажатии
    При coyoteTimer > 0: vx = −jumpForce × gravityDir  (отталкивает от стены)
    При canDoubleJump:   vx = −djForce × gravityDir

  Variable jump (отпускание Space):
    if (!Space && vx × gravityDir < −4): vx += gravityDir × 0.9

  Гравитация: vx += gravity × gravityDir  каждый кадр
  Ограничение скорости падения: vx × gravityDir <= 18

  Порядок коллизий за кадр:
    1. y += vy → _resolveY_slide(platforms)   — блокировка по Y (без onGround)
    2. x += vx → _resolveX_land(platforms)    — приземление на стену (с onGround)

  _resolveX_land(platforms):
    movingWithGravity = (vx × gravityDir > 0)
    если movingWithGravity:
      gravityDir > 0: player.x = platform.x − player.w   (правая стена)
      gravityDir < 0: player.x = platform.x + platform.w (левая стена)
      vx = 0; onGround = true; вызов platform.onPlayerLand()
    иначе (встречное столкновение):
      gravityDir > 0: player.x = platform.x + platform.w
      gravityDir < 0: player.x = platform.x − player.w
      vx = 0

  _resolveY_slide(platforms):
    если коллизия: если vy > 0: player.y = platform.y − player.h
                   иначе:       player.y = platform.y + platform.h
    vy = 0

Поворот персонажа (Player.draw, player.js):
  if (gravityAxis === 'x') {
    angle = (gravityDir > 0) ? −Math.PI/2 : Math.PI/2
    ctx.translate(cx, cy); ctx.rotate(angle); ctx.translate(−cx, −cy)
  }
  Ноги (нижняя часть фигурки) направлены к активной стене.

Визуал стен (game.js):
  Функция drawActiveWall() + вспомогательная _drawWallSurface()
  Порядок вызова: после level.platforms.forEach(draw), до hazards/checkpoints/player

  _drawWallSurface(isLeft, isFloor, pulse):
    FLOOR_W = 28 px (активная стена), CEILING_W = 14 px (неактивная)
    x = isLeft ? 0 : W − W_STRIP
    Активная стена (isFloor=true):
      Цвет: isLeft → rgb(50,200,130), иначе → rgb(220,130,50)
      Полоса W_STRIP × H с горизонтальными тайлами каждые 40 px
      Смещение тайлов: cam.y % 40  (тайлы скроллятся с камерой)
      Яркая внутренняя грань 3 px; мягкое свечение 90 px наружу
    Неактивная стена (isFloor=false):
      Цвет: rgb(40,55,80); стрелки ← → каждые 100 px

Флажок чекпоинта (Checkpoint.draw, entities.js):
  Добавлено свойство drawAngle (по умолчанию 0 — нет поворота)
  При drawAngle != 0:
    ctx.save()
    ctx.translate(cx, cy); ctx.rotate(this.drawAngle); ctx.translate(−cx, −cy)
    рисуем шест и флажок как обычно
    ctx.restore()
  Для левой стены: drawAngle = Math.PI/2   (+90°, основание влево)
  Для правой стены: drawAngle = −Math.PI/2  (−90°, основание вправо)
  Задаётся в levels.js через Object.assign:
    Object.assign(new Checkpoint(x, y), { drawAngle: Math.PI / 2 })

Граничные платформы Сна 6:
  Ширина стен = 28 px (совпадает с FLOOR_W визуальной полосы)
  Левая стена:  Platform(0, 0, 28, levelHeight)       — player.x = 28 при приземлении
  Правая стена: Platform(levelWidth−28, 0, 28, levelHeight) — player.x = levelWidth−28−player.w
  Все объекты левой стены: x = 28
  Все объекты правой стены: x = levelWidth − 28 − objectWidth

16. Катсцена пробуждения
После прохождения последнего уровня запускается процедурная катсцена ~10 секунд:
Тёмная комната с кроватью у окна, спящий персонаж, дрейфующие "сонные" частицы
Глаза моргают, затем открываются
Персонаж садится в кровати, одеяло отодвигается
Постепенный рассвет: небо светлеет, поднимается солнце, лучи протягиваются в комнату
Текстовая нарративка: "Сон рассеивается" → "Ты открываешь глаза" → "Утро. Ты в своей комнате" → "Но ночь снова придёт..."
Финальное забеливание экрана → возврат к интро-экрану (игра начинается заново)
Скип через Space/W/↑ после первой секунды
Сопровождается отдельной тревожной процедурной музыкой
